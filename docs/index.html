Elephant Central: twelve changes to test

Get Living would like to improve conversion on the Elephant Central neighbourhood page and plans to A/B test whatever changes it makes. This mockup shows twelve changes to the page's layout, wording and calls to action. All of them use components the page already has. None of them is a new feature.

How to use the mockup

The mockup is a working copy of the Elephant Central page, rebuilt closely enough to recognise, with Get Living's global header and footer left out. The bar at the top switches between Today and Proposed, and the Changes button opens a panel where each change can be turned on or off, so any combination can be seen before it is built.

Switching Notes on adds a note beside each change explaining what it is, why it should help conversion, what to measure and how much effort it is likely to be. Changed elements are outlined and numbered while notes are on. Two notes in red are open questions for Get Living.

Prices and availability are as shown on Find a home on 22 October 2026. The HomeViews rating is Get Living's portfolio-wide score as of September 2026. Photography is Get Living's own, loaded from getliving.com; anywhere it cannot load, a coloured placeholder shows instead.

A note on effort

We cannot see how the page is built, so we do not know for certain which changes are a CMS edit and which need a developer. Each change is labelled with our best guess:

  • CMS editVery likely a content change in WordPress, with no development. (2)
  • HubSpot settingA form setting in HubSpot, with no development. (1)
  • Check with developersA CMS edit if the component already supports it, otherwise a small template change. (8)
  • Small front-end changeNeeds a developer, but no new feature. (1)

Get Living's developers will know the answer for most of the "check" items straight away, and a short run through the list with them would firm these up before anything is scheduled.

How we would test them

We have grouped the changes into three rounds rather than proposing twelve separate tests. A single neighbourhood page is unlikely to get enough traffic to test small changes one at a time and reach a clear result in a sensible time, and several of the changes depend on each other: moving the homes up the page matters more once the cards show prices. Testing in rounds reaches a result sooner.

The trade-off is that a winning round does not tell you which of its changes did the work. If traffic allows, the larger changes in a winning round can be tested on their own afterwards. Get Living's analytics will say how much traffic the page gets, and so how long each round would need to run.

Agree the measure first

  • Primary: enquiry form submissions from this page.
  • Secondary: click-through to the Elephant Central listings, since a renter who finds a home there may enquire from the listing instead.
  • Alongside: enquiry quality, as judged by the lettings team. Showing prices may reduce the number of enquiries while improving them, and it is worth deciding in advance whether that counts as a win.

What we have left out

The map view, saved homes, viewing booking and the new neighbourhood template from our earlier prototypes are new features, so they are not part of this. They remain in the earlier prototype pack should the scope change. The changes here are compatible with them, and several (prices on the cards, journey times, a residents' rating) are smaller versions of the same ideas.
